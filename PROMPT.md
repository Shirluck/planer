# Промт для Claude Code

Скопируйте всё, что ниже линии, целиком в Claude Code, запущенный в папке проекта `planner-desktop`.

---

Ты senior full-stack разработчик (Electron + чистый JS/HTML/CSS). Работай автономно: принимай решения сам по правилам из раздела «Решения по умолчанию», вопросы задавай только если без ответа невозможно продолжить (нужен внешний доступ, действие необратимо и неочевидно).

## Цель

Довести десктопное приложение «Планер» до состояния, когда:
1. Внутри каждой задачи есть **доска в стиле Milanote**: свободный холст, на котором можно размещать карточки — заметки, чек-листы, **фото, видео, зарисовки**, ссылки.
2. Приложение собирается в **Windows `.exe`** (установщик и portable), запускается двойным кликом и проходит автоматические проверки.

Ощущение от продукта: Milanote, но проще и быстрее; всё локально, без аккаунтов; интерфейс на русском; аккуратный, не «шаблонный» дизайн (сохрани существующую палитру, шрифты и токены из `index.html`, поддержи светлую и тёмную темы).

## Сначала разберись в проекте

1. Прочитай `CLAUDE.md` и весь код (`index.html`, `shim.js`, `main.js`, `preload.js`, `package.json`). Это небольшой проект, прочитай его целиком, а не выборочно.
2. Выполни `git init`, закоммить исходное состояние (`chore: baseline`). Дальше коммить после каждого этапа с понятным сообщением, чтобы можно было откатиться.
3. `npm install`, запусти `npm start`, убедись, что приложение открывается. Если что-то не работает на этом шаге, исправь это до начала новых функций.
4. Кратко выведи план по этапам (5–10 строк) и сразу переходи к работе, подтверждения не жди.

## Этап 1. Вложения и доска внутри задачи

**Как это выглядит для пользователя**
- На строке задачи (колонки «Сегодня» и «Неделя») рядом с флажком приоритета и заметкой появляется кнопка «Доска» (иконка скрепки/холста). Если на доске что-то есть, значок остаётся видимым и показывает число карточек.
- Клик открывает доску задачи в большом окне поверх приложения (как редактор страниц): сверху название задачи (редактируется), панель инструментов, ниже холст. `Esc` и клик по фону закрывают.
- Холст: перемещение (зажатый пробел + мышь, средняя кнопка или перетаскивание пустого места), масштаб (`Ctrl` + колесо, кнопки «+», «−», «100%», «Показать всё»). Лёгкая точечная сетка на фоне.
- Карточки: перетаскивание, изменение размера за угол, выделение (клик, рамка выделения, `Shift` для добавления), удаление (`Delete`), дублирование (`Ctrl+D`), копирование и вставка (`Ctrl+C` / `Ctrl+V`), порядок слоёв (на передний/задний план), цвет у заметок (5–6 мягких цветов).
- Типы карточек:
  - **Заметка**: текст с простым форматированием (жирный, список, чекбокс). Двойной клик по пустому месту холста создаёт заметку.
  - **Чек-лист**: заголовок и пункты с галочками, прогресс.
  - **Изображение**: png, jpg, webp, gif, avif, svg. Подпись под картинкой (необязательно). Двойной клик открывает просмотр во весь экран с зумом.
  - **Видео**: mp4, webm, mov, mkv. Постер-кадр в карточке, воспроизведение по клику, встроенные элементы управления, перемотка. Если кодек не поддерживается (например HEVC), показать понятное сообщение и кнопку «Открыть во внешнем плеере» (`shell.openPath`).
  - **Зарисовка**: см. этап 2.
  - **Ссылка**: вставленный URL превращается в карточку с доменом; открытие во внешнем браузере (только `https:` и `http:`). Загрузку превью страниц не делай, это внешний сетевой доступ.
- Добавление файлов: кнопка «Фото / видео» (выбор нескольких файлов), **перетаскивание файлов с рабочего стола или из проводника на холст** (карточка появляется там, куда бросили), **вставка из буфера обмена `Ctrl+V`** (скриншоты, скопированные картинки). Несколько файлов раскладываются аккуратной сеткой без наложений.
- Для файлов с диска (перетаскивание из проводника, выбор через кнопку) получай путь через `webUtils.getPathForFile(file)` в `preload.js` (в новых версиях Electron свойство `file.path` убрано) и копируй файл в основном процессе. Для картинок в буфере и перетаскиваний из браузера, где нет пути к файлу, передавай данные в основной процесс через `ArrayBuffer`.
- Отмена и повтор действий на доске: `Ctrl+Z` / `Ctrl+Shift+Z` (перемещение, изменение размера, добавление, удаление, правка текста). Минимум 50 шагов.
- Всё сохраняется автоматически (с отладкой по времени), индикатор «Сохранено» в шапке приложения продолжает работать.

**Как хранить (важно, делай именно так)**
- Файлы медиа **не кладутся в JSON и не кодируются в base64**. Основной процесс копирует файл в `%APPDATA%\Planer\media\<sha256>.<ext>` (одинаковые файлы хранятся один раз), копирование потоковое (`fs.createReadStream`), без загрузки всего файла в память. Большие файлы (> 200 МБ) показывают прогресс; предел одного файла 2 ГБ с понятным сообщением при превышении.
- В данных хранится только ссылка: `{ id, type, x, y, w, h, z, mediaId, name, mime, size, width, height, duration, caption, ... }`.
- Доска задачи хранится **отдельным документом** (`board-<taskId>`), а не внутри списка задач, чтобы списки оставались лёгкими. В задаче хранится только лёгкая сводка (`boardCount`). Структура доски: `{ v: 1, view: {x, y, zoom}, items: [...] }`.
- Для отдачи медиа в страницу зарегистрируй собственную схему `media://<id>` (`protocol.registerSchemesAsPrivileged` со `standard`, `secure`, `supportFetchAPI`, `stream`; обработчик через `protocol.handle` и `net.fetch` на `file://`-путь). Проверь, что **перемотка видео работает** (нужна поддержка Range-запросов), иначе сделай обработчик с ручной отдачей диапазонов.
- Защита: `id` проверяется регулярным выражением (`^[a-f0-9]{64}$`), никаких путей от страницы, защита от выхода за пределы папки `media`, белый список MIME-типов и расширений, проверка сигнатуры файла (магические байты) для изображений и видео. Страница не получает доступа к Node.js (оставь `contextIsolation: true`, `sandbox: true`). В CSP добавь только `img-src ... media:` и `media-src media:`, остальное не ослабляй.
- Миниатюры: для изображений создавай уменьшенную копию (до 512 px по длинной стороне, `nativeImage` в основном процессе) в `media/thumbs/`, на холсте показывай миниатюры, в просмотре оригинал. Для видео постер-кадр получай через `<video>` + `<canvas>` и тоже кэшируй миниатюрой.
- Сборка мусора: файл удаляется с диска, только если на него не осталось ссылок ни из одной доски **и** прошло 7 дней после последнего использования (это нужно, чтобы работала отмена удаления). Проверка при запуске, без блокировки интерфейса.
- Миграция: в данные добавь поле `schema` (версия). Существующий `planner-data.json` должен продолжать работать без потерь; перед любой миграцией делай копию в `backups/`.
- Сохранение данных остаётся атомарным и с отладкой по времени. Не переписывай при каждом изменении всё подряд: если единый `planner-data.json` становится узким местом из-за досок, раздели хранилище на отдельные файлы документов (`docs/<имя>.json`) с атомарной записью, сохрани совместимость со старым файлом (импорт при первом запуске).

## Этап 2. Зарисовки

Карточка «Зарисовка» открывает редактор рисования (модальное окно поверх доски; `Esc` закрывает с сохранением, отдельная кнопка «Отмена» отбрасывает правки).

- Инструменты: перо, маркер (полупрозрачный), ластик (по штрихам и по пикселям на выбор), линия, стрелка, прямоугольник, эллипс, текстовая подпись, пипетка. Палитра цветов (6–8 приятных цветов + выбор любого), толщина (слайдер с предпросмотром кисти).
- Ввод через **Pointer Events**: мышь, сенсорный экран и перо (Wacom, Surface Pen) с **учётом нажима** (`pressure`) и сглаживанием линий (Catmull-Rom или квадратичные кривые), `touch-action: none`, без дрожания и «лесенки» (учитывай `devicePixelRatio`).
- Отмена и повтор (`Ctrl+Z` / `Ctrl+Shift+Z`), очистка, масштаб и перемещение холста редактора, фон: прозрачный, белый, клетка, линейка.
- **Рисование поверх изображения**: в карточке изображения кнопка «Нарисовать поверх» открывает тот же редактор с картинкой как фоном. Оригинал не изменяется, штрихи хранятся отдельным слоем.
- Хранение: штрихи как векторные данные (массивы точек с нажимом, цвет, толщина, инструмент), чтобы зарисовку можно было **снова редактировать**; готовый PNG с прозрачным фоном рендерится в `media/` и используется для показа на доске. Размер данных штрихов ограничь прореживанием точек.
- Экспорт: на любой карточке с изображением или зарисовкой пункт «Сохранить как…» (диалог сохранения, PNG), а также «Копировать в буфер».

## Этап 4. Сборка `.exe`

- Настрой `electron-builder` для Windows x64: цели `nsis` (установщик, **per-user, без прав администратора**, `oneClick: false`, можно выбрать папку, ярлыки на рабочем столе и в меню «Пуск», языки установщика: русский и английский) и `portable` (один `.exe` без установки).
- Имена файлов ASCII, без кириллицы: `dist/Planer-Setup-${version}.exe` и `dist/Planer-${version}-portable.exe`. Отображаемое имя продукта «Планер».
- **Иконка**: нарисуй сам. Логотип из четырёх цветных квадратов (как в шапке приложения) на скруглённом фоне. Сгенерируй `build/icon.png` (1024×1024) и `build/icon.ico` с размерами 16, 24, 32, 48, 64, 128, 256 (используй `sharp` и `png-to-ico` или аналог; зависимости только из npm). Иконка нужна окну, панели задач, установщику и ярлыкам.
- Версия приложения из `package.json`; в окне «О программе» (меню) показывай версию. `asar: true`, исключи из сборки тесты, скриншоты и мусор.
- Подпись кода не нужна. Предупреждение SmartScreen при первом запуске нормально, опиши в `README.md`, как его обойти.
- Добавь скрипты: `npm run dist` (всё), `npm run dist:dir` (быстрая распакованная сборка в `dist/win-unpacked` для проверок).
- **Собери и проверь**: запусти `npm run dist`, затем запусти `dist/win-unpacked/*.exe` под управлением Playwright (`_electron.launch({ executablePath })`) и убедись, что окно открылось, данные сохранились и перезагрузились, медиа показывается из упакованного приложения (в `asar` нет путей, ломающихся после упаковки).
- Установщик по возможности проверь тихой установкой в временную папку (`/S /D=...`), затем запуск и удаление. Если это недоступно в твоём окружении, честно напиши, что не проверено.

## Решения по умолчанию (не спрашивай)

- ОС: Windows 10/11 x64. Код должен оставаться кроссплатформенным (macOS и Linux не ломать).
- Electron и electron-builder: последние стабильные версии. Новые зависимости только из npm и только если без них заметно хуже (допустимы `sharp`, `png-to-ico` для сборки). **Во время работы приложения лишних зависимостей и сетевых запросов не должно быть**, кроме запросов ассистента к `api.anthropic.com`.
- Фреймворки интерфейса (React, Vue и т.п.) не добавляй: проект на чистом JS. Файл `index.html` разрастётся: разрешено вынести код в модули (`/src/*.js`, `/src/*.css`) с простой сборкой (`esbuild`) или без неё, если это улучшает читаемость. Если используешь ES-модули напрямую, сначала проверь, что они загружаются с `file://` при текущей CSP; если нет, собирай в один файл через `esbuild`. Рефакторинг делай отдельным коммитом и только при зелёных тестах.
- Язык интерфейса и сообщений: русский. Идентификаторы и комментарии к коду: английские идентификаторы, комментарии по-русски допустимы.
- Холст доски реализуй на DOM + CSS `transform` (карточки как элементы) и отдельный `<canvas>` только для редактора рисования. Не тащи тяжёлые библиотеки холста.
- Данные существующих пользователей не теряются никогда. Любое удаление пользовательских файлов только через путь с отменой (см. сборку мусора).

## Качество

- Плавность: пан и зум доски на 100+ карточках без заметных лагов (используй `will-change`, `requestAnimationFrame`, ленивую загрузку миниатюр через `IntersectionObserver`).
- Доступность: фокус с клавиатуры, `aria-label` у кнопок, контраст не ниже AA, уважай `prefers-reduced-motion`. Основные действия доступны без мыши там, где это разумно.
- Ошибки показывай человеческим языком (не удалось скопировать файл, нет места на диске, неподдерживаемый формат), без падений. Ни одно исключение не должно закрывать приложение или терять данные.
- Не добавляй телеметрию, аналитику, автообновления, внешние шрифты и CDN.

## Проверка (обязательна)

1. Настрой автотесты на Playwright для Electron (`@playwright/test`, `_electron`), запуск `npm test`. Сценарии минимум: создать задачу, открыть доску, добавить заметку, добавить изображение (через `setInputFiles`/IPC), добавить видео, создать зарисовку и перерисовать её заново, переместить и изменить размер карточки, отмена/повтор, закрыть и перезапустить приложение (данные на месте), удалить карточку и отменить удаление, повреждённый и пустой файл данных (приложение стартует), файл неподдерживаемого типа (понятная ошибка).
2. Сгенерируй тестовые файлы сам (PNG через `sharp`/`canvas`, короткое видео через `ffmpeg`, если он есть; если нет, используй готовый маленький `webm`, создаваемый в браузере через `MediaRecorder` из canvas).
3. Сделай скриншоты ключевых состояний (главный экран, доска с карточками, редактор рисования, просмотр изображения; светлая и тёмная темы; окно 1280×800, 1920×1080 и минимальный размер) в `tests/screens/`, **открой их и оцени глазами**: выравнивания, обрезания текста, наложения, читаемость. Исправь найденное.
4. Прогони проверки безопасности: попытка запросить `media://../../something`, id не по формату, файл с неверным расширением, огромный файл. Всё должно отклоняться без падений.

## Критерии готовности

- `npm start` запускает приложение; `npm test` зелёный; `npm run dist` создаёт установщик и portable `.exe`; запуск из `dist/win-unpacked` проходит сквозной тест.
- Все ранее существовавшие функции работают (колонки, чек-листы, приоритеты, заметки к задачам, папки и страницы, перетаскивание, отмена удаления, ассистент, смена ключа API, резервные копии).
- Все функции доски и зарисовок из этапов 1–2 работают и переживают перезапуск.
- `README.md` обновлён: запуск, сборка, где лежат данные и медиа, горячие клавиши доски, поддерживаемые форматы, известные ограничения.

## Чего не делать

- Не храни медиа в base64 и не кладите их в JSON.
- Не ослабляй `contextIsolation` / `sandbox` и CSP сверх сказанного.
- Не удаляй и не перезаписывай пользовательские данные без копии.
- Не переписывай проект с нуля и не меняй дизайн-токены без причины.
- Не объявляй задачу готовой, пока не запустил тесты и сборку сам и не посмотрел скриншоты.
